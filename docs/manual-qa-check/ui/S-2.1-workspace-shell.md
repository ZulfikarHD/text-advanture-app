# Manual QA — E2.1: Authoring Workspace Shell

> **Domain:** `ui` · **Stories:** S-2.1.1 (per-story workspace + navigation), S-2.1.2 (play-readiness checklist)
> **Date:** 2026-06-06 (Asia/Jakarta) · **Tester:** _____________ · **Build:** E2.1
> **Rule:** every step uses a visible navigation action (link/button/tab). **No step types a URL to reach a page.** The workspace is reached by opening a **story card** on the Workspace dashboard, then using the per-story tab bar.

## Preconditions

- App running (`composer run dev`) on MariaDB; assets built (`pnpm build` or `pnpm dev`).
- Signed in with a known account that owns **at least one story** (create one from the Workspace dashboard if needed).
- The global **Settings → Model roles** are seeded (Sprint 6) so the readiness happy path can resolve.

## TC-4 — Play-readiness checklist on Overview · S-2.1.2

| # | Action (navigation) | Expected |
|---|---------------------|----------|
| 1 | On a **new/empty** story's **Overview**, read the **readiness panel** | A **"Not yet playable"** state with an **Incomplete** badge and a checklist: ≥1 character; a chapter with a scene **and a beat**; a resolvable model for every role — each row met/unmet with a teaching detail |
| 2 | Add a character and a chapter + scene **but no beat** (via seed/factory or future surfaces) and reopen Overview | The **structure** requirement still reads unmet ("Add a chapter, scene, and beat…") — a scene alone is not enough |
| 3 | (If you have a fully complete story) open its Overview | The panel flips to **"Ready to play"** with a **Play-ready** badge and every row checked |

**Pass criteria:** unmet requirements are enumerated with next-step detail and recomputed on each read; a scene-without-beat is not play-ready; a complete story flips to ready. No native alert.
**Result:** ☐ Pass ☐ Fail — Notes: ____________________

## TC-6 — Ownership isolation (automated-backed)

Foreign-story access (404 on every workspace surface for a story you don't own) would require typing another owner's URL, which this checklist forbids, so it is locked by automated tests instead:

- `tests/Feature/Stories/StoryWorkspaceTest.php` — each placeholder surface renders for the owner with its descriptor; **404 on a foreign story**; guest redirect to login.
- `tests/Feature/Stories/StoryOverviewTest.php` — readiness true vs. unmet (no character / **scene but no beat** / no resolvable model); **404 on a foreign story**.

**Manual evidence:** while signed in, no visible navigation exposes another owner's story workspace.
**Pass criteria:** the Stories suite is green; no navigation leaks cross-owner content.
**Result:** ☐ Pass ☐ Fail — Notes: ____________________

## UX / Law-of-UX observations

- **No dead nav items:** unbuilt surfaces are reachable teaching pages, not links to nowhere. ✔
- **No native alerts:** placeholders use the shared `EmptyState`; readiness is an inline panel. ✔
- **Single primary action** (Hick's): each placeholder offers one **Back to overview** action. ✔
- **Reachable by navigation:** every surface is a tab opened from a story card — no URL typing. ✔
- **Touch targets:** tabs and the back button are `h-11` (≥44px). ✔
- **Tokens + dark parity:** all surfaces use semantic tokens (no hardcoded colors). ✔

## UX Critical Violation check

> **None found.** Every surface is reached through visible navigation (story card → workspace tabs). Placeholder surfaces are reachable teaching states, not dead links. The foreign-story 404 isolation, which would require typing another owner's URL to demo, is validated by automated tests.
