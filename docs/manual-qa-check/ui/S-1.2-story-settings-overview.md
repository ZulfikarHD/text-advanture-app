# Manual QA — E1.2: Per-story Settings & Overview

> **Domain:** `ui` · **Stories:** S-1.2.1 (story settings), S-1.2.2 (story overview)
> **Date:** 2026-06-06 (Asia/Jakarta) · **Tester:** _____________ · **Build:** E1.2
> **Rule:** every step uses a visible navigation action (link/button/tab). **No step types a URL to reach a page.** The workspace is reached by opening a **story card** on the Workspace dashboard, then using the **Overview · Details · Settings** sub-nav.

## Preconditions

- App running (`composer run dev`) on MariaDB; assets built (`pnpm build` or `pnpm dev`).
- Signed in with a known account that owns **at least one story** (create one from the Workspace dashboard if needed).
- The global **Settings → Model roles** are seeded (Sprint 6) so resolution can succeed for the readiness happy path.

## TC-6 — Settings: per-role model override + fallback · S-1.2.1

| # | Action (navigation) | Expected |
|---|---------------------|----------|
| 1 | On **Settings**, find a role card with its **Override** checkbox **off** | The card shows the **global default** it falls back to (or a "No global default" badge) — fields hidden |
| 2 | Tick **Override** for one role | Model slug + temperature + max-tokens + **Active** fields appear, pre-filled from the global default |
| 3 | Change the slug → **Save settings** | Success toast; reopening Settings shows the override retained (checkbox stays on with your value) |
| 4 | Untick **Override** for that role → **Save settings** | The card returns to the **global fallback** summary; the per-story row is removed (role now uses the global default again) |
| 5 | Tick **Override**, clear the **model slug**, **Save** | An inline validation error ("Choose a model slug for every role you override.") via `InputError` + the `AlertError` summary; nothing saved for that row |

**Pass criteria:** override on persists a per-story value; off restores the global fallback; required-when-overriding fails gracefully inline.
**Result:** ☐ Pass ☐ Fail — Notes: ____________________

## TC-7 — Ownership isolation (automated-backed)

Foreign-story access (404 on Overview / Details / Settings for a story you don't own) would require typing another owner's URL, which this checklist forbids, so it is locked by automated tests instead:

- `tests/Feature/Stories/StorySettingsTest.php` — renders for owner; **404 on a foreign story** (edit + update); guest redirect; POV persistence; override create / precedence / clear; required-slug validation.
- `tests/Feature/Stories/StoryOverviewTest.php` — derived counts; readiness true vs. unmet (no character / no resolvable model); **404 on a foreign story**.

**Manual evidence:** while signed in, no visible navigation exposes another owner's story workspace.
**Pass criteria:** the Stories suite is green; no navigation leaks cross-owner content.
**Result:** ☐ Pass ☐ Fail — Notes: ____________________

## UX / Law-of-UX observations

- **No native alerts:** every result is a `sonner` toast or inline `InputError` / `AlertError`. ✔
- **Single primary action** (Hick's): Settings has one **Save settings**; Details one **Save changes**. ✔
- **Empty/teaching states:** an empty story's readiness panel enumerates the next steps rather than showing a blank gate. ✔
- **Reachable by navigation:** the workspace opens from a story card; every surface is a tab — no URL typing. ✔
- **Touch targets:** POV select, inputs, tabs, and the save button are `h-11` (≥44px). ✔
- **Tokens + dark parity:** all surfaces use semantic tokens (no hardcoded colors). ✔

## UX Critical Violation check

> **None found.** All surfaces are reached through visible navigation (story card → Overview · Details · Settings tabs). The foreign-story 404 isolation, which would require typing another owner's URL to demo, is validated by automated tests.
