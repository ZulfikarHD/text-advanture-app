# S-3.1.1 — Session state machine spine Test Plan

> **Feature:** [../features/session/S-3.1.1-state-machine-spine.md](../features/session/S-3.1.1-state-machine-spine.md) · **Last Updated:** 2026-06-07

## Scope

Covers the deterministic spine transitions in `SessionStateMachine`: node + position changes for `begin` / `applyHandoff` / `resumeFromPlayerMoment` / `completeBeat`, the `npc_moment` rejection, fail-closed guards on out-of-order calls, document-order beat advance + terminal hold, and one full single-conductor cycle (S-3.1.2). Not covered: prose/handoff generation (S-4.2.1), player input commit (S-5.1.1), resume-anchor content (S-5.3.1), Play UI (S-5.4.1).

## Preconditions / fixtures

A `PlaySession` parked on a chosen `state_node` and positioned at an authored beat. Helpers build a story with one chapter/scene/beat (`singleBeat`), two ordered beats in one scene (`twoBeatsInOneScene`), or beats across chapters for the document-order walk. No LLM, no auth, no model-role seeding needed — the spine is a backend service driven directly.
