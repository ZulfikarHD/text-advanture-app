Directed Interactive Novel Engine — Architecture Brief v3.1

Handoff document · June 2026 · Status: full design drafted — NPC behaviour (ADR 0001–0010), tech/persistence (0011–0012), the authoring + narrator side (0013–0016: compile pipeline, internal-state schema, beat document, narrator turn loop), and the LLM client + authoring tools (0017–0020: OpenRouter/LlmClient, character creation + archetypes, outline compilation, prompt block registry). All ADRs are Proposed (planning stage); what remains is implementation + the O4 UI ADR. Full decision log lives in docs/adr/ — this brief is the snapshot; the ADRs hold the why.

Project summary

A custom interactive fiction engine built on top of the Claude API. Not a SillyTavern config — a purpose-built web app. The player experiences a story chapter-by-chapter with authored prose quality, player input moments, and NPC agent turns. A hidden beat document steers all agents toward chapter goals without explicit plot instructions. v3 closes the full NPC behaviour subsystem: how a character is, feels, changes, scars, and expresses — and how all of that compiles into a single in-character LLM call. v3.1 adds the Narrator's first pieces — a directed-pressure nudge (the only authorial steering channel), per-scene POV projection, and the recorder — establishing three leak guards (own feelings · authorial omniscience · others' hidden truth) and one shared human review gate.

Three agents — layered context isolation core

Different agents see different slices of truth. "Sees" means "acts within the limits of what it knows" — an NPC cannot act on information outside its context boundary. The NPC context assembler (ADR 0007) is the mechanical enforcement point: it only ever reads the acting NPC's own data + what it witnessed.

NARRATOR     → sees: beat doc (full), full relationship mesh, scene history,
                      player inputs, NPC responses as story events
               uses mesh for: atmosphere, body language, room dynamics only
               rule: never reveal info a character would not know

PLAYER (you) → sees: rendered prose only

NPC agent    → sees: own character card, own relationship snapshot (self-perspective only),
                      psychological nudge from beat doc, witnessed scene excerpt
               does NOT see: beat doc, other character cards, other characters' relationships,
                             narrator instructions

Session state machine core

[SESSION_START]
      ↓
[NARRATOR_TURN] → generates prose → scans for handoff signal
      ↓
   branches to:
      ├── [PLAYER_MOMENT]   → render input box → wait → [NARRATOR_RESUMES]
      ├── [NPC_MOMENT]      → run interaction queue → resolve turns → [NARRATOR_RESUMES]
      └── [BEAT_COMPLETE]   → chapter wrap → summary generated

Data model — three layers ADR 0001

Split by lifecycle and ownership, not by "it's all character data." The full authored bible (e.g. luna-archi.md) is never injected — it is the human's source. The runtime card is a compiled, spoiler-free, current-state slice of it.

SOURCE BIBLE   → full authored doc, all arcs. Human-facing. NEVER injected.
CHARACTER CARD → compiled current-state slice. Immutable at runtime.
                 Includes knowledge_boundary (what the character knows / does NOT know now).
RELATIONSHIP   → mutable, per DIRECTED pair (from → to). Written at scene/session boundaries.
   EDGES
INTERNAL STATE → mutable, per character. Transient: active emotions, motivation, masks.
                 Decays on its own clock.

The player has an appearance-only card and no simulated outgoing edges — the human supplies their own behaviour; NPCs only hold edges toward the player.

Relationship edge schema ADR 0002

Directed and owner-perspective (how from sees to, possibly self-deceived). A→B ≠ B→A. Only the live axes for that edge are instantiated. Behaviour is not the number alone:

rendered behaviour = axis value  ×  expression mask  ×  (card voice + relational register)
edge:  from: luna-archi   to: vixia-archi
  register: { base: transparent_mess, overrides: [...] }     # behavioral grammar (ADR 0006)
  axes:
    affection:
      value: 96                 # -100..+100, owner self-perceived
      awareness: { mode: auto } # auto (derive tier from |value|) | capped (feels, can't access)
      bounds: { soft_floor: 88, soft_cap: 100, hard_floor: 40, hard_cap: 100 }
      rates:  { gain: 0.4, loss: 0.2 }     # asymmetric per axis (trust: gain low / loss high)
      peak:   { up: 96, down: 0 }          # high-water marks (latch source, ADR 0004)
      scar:   { latched: true, floor: 57 } # permanent floor once peak crosses threshold
      baseline: 0                          # decay pulls toward here, stops at scar floor
  topic_flags: [ { topic: the_diagnosis, effect: knows_but_wont_admit } ]   # edge-scoped masks
  meta: { seeded_from: vixia_sibling_bond, pending_drift: {} }

Awareness is computed from value at read time (tiers below); mode: capped models blind spots (feels strongly, cannot consciously reach it). Bounds are invisible to the character — they are authorial. New edges are seeded from disposition priors on the card, keyed by traits of the target (gender, demeanor, faction, shows-interest) — not born neutral.

Emotion axes — full model core

All axes run from -100 to +100. Negative values reverse meaning. Some axes are directional by nature (rivalry, debt) and approach zero rather than going negative. Which axes are "live" is declared on the card.

TrustActively deceives, manipulatesNeither trusts nor distrustsConfides everything
FearReckless contempt, no cautionNo fearParalyzed, avoids
RespectDismisses judgment entirelyNeutral regardDefers to their judgment

Meaningful contradictions — do not resolve, surface them

HIGH AFFECTION + LOW TRUST      "I love you but can't believe a word you say."   (Luna's default)
HIGH FEAR + HIGH AFFECTION      "I'm drawn to them but they terrify me."
HIGH TRUST + NEGATIVE AFFECTION "I rely on their judgment but can't stand them."
HIGH RIVALRY + HIGH AFFECTION   "My favorite person is also my greatest competition."
HIGH DEBT + NEGATIVE AFFECTION  "I owe them everything and I hate that I do."

Awareness tiers core ADR 0002/0007

Characters don't have full conscious access to all their feelings. Awareness is per-axis, computed from value by default, overridable to capped for blind spots. In the assembled prompt awareness is folded into the wording (so a capped feeling is never stated plainly and can't leak); in the data it stays a separate field.

RangeAwareness levelPrompt language
0–39No felt signalBehavior exists but character would deny or not notice it
40–59Vague unease / warmth"Something feels off / right but I can't name it"
60–79Subconscious recognitionFeels it, acts on it instinctively, rationalizes it away if asked
80+Conscious awarenessKnows. May suppress or act on it deliberately.

Caps, floors & latched scars ADR 0004

Each axis has two-tier bounds. Drift (ordinary events) is clamped to soft bounds; only a rupture (high-impact event) reaches the soft↔hard band and may rewrite bounds. High feelings leave permanent marks via a single latch mechanism:

LATCH      when an axis's peak crosses latch_threshold → set a permanent floor (a "scar")
COMMITMENT = a positive latch   (affection peaks high → high floor → won't abandon over slights)
TRAUMA/PTSD = a high-magnitude latch (fear peaks high → permanent floor → lingering flaw)
DECAY      pulls value toward baseline but STOPS at the latched floor (acute fades, scar stays)
TRIGGERS   stored on a scar can rupture-spike the value back toward peak ("something reminds her")
OVERCOME   only a deliberate growth-arc rupture clears a latched floor — time/drift cannot
EFFECTIVE FLOOR = max(static soft_floor, scar.floor)

Time = narrative time. Decay is computed at scene/chapter boundaries and scaled by declared in-world elapsed time (a "three weeks pass" timeskip), not by beat count. Committed edges and latched floors are decay-exempt.

Two channels move every axis, with different rules:

The appraisal LLM never writes the edge directly — it emits proposals; a review gate sits before commit:

appraisal LLM → delta proposals → REVIEW gate (accept / edit / reject) → commit (+ audit log)

proposal: { edge, axis, direction, magnitude, channel, trigger, confidence }
  trigger is MANDATORY — every axis movement is explainable; the log feeds the relationship viewer.

Trigger taxonomy ADR 0005

TWO LAYERS   universal priors (shared) + character sensitivities (on the card)
SENSITIVITY  { id, detect (natural language), targets, axes+direction, weight, channel }
TARGETS      actor | beneficiary | witnessed_third_party  (vicarious shifts supported)
DRIFT vs RUPTURE  magnitude ≈ weight × LLM-judged severity, against a shared severity rubric;
                  betrayal / confession / abandonment are categorically rupture
SALIENCE     match-only — no matched sensitivity → no delta (characters are numb to what they
             don't care about)
CONFLICTS    multiple sensitivities may fire → multiple proposals (this MANUFACTURES the
             meaningful contradictions; do not resolve them)
RUNTIME      ruptures can INSTALL new sensitivities (a scar's re-spike triggers) — appraisal
             both reads and writes sensitivities
LOOP CLOSURE the matched sensitivity names itself as the proposal's `trigger` string

Expression mask layer core

Separates what a character feels (internal state) from what they express (behavior output). Resolves contradictions like trust=100 but cannot tell the truth. Sources: card traits, active emotional states (guilt/grief/shame), external obligations (sworn to secrecy), and self-deception (below awareness threshold). Narrow, topic-scoped masks live on the edge as topic_flags.

INTERNAL STATE   trust: +100
MASK             guilt modifier active on topic [the merchant]
RESULT PROMPT
  "Trusts completely and wants to tell the truth. But guilt stops her — not lack of trust,
   inability to face it herself. The more she trusts them, the more it costs her to stay silent.
   She deflects warmly, changes the subject with a smile."

Register / relational-mode system ADR 0006

The layer that turns numbers back into behaviour. A register is a profile across a fixed canonical dimension set — the grammar of how a character expresses, independent of how much they feel. (Luna's "Koakuma vs. With-Vixia" contrast table is literally a two-register spec.)

DimensionValues
disclosuresealed · guarded · open · transparent
proximitycontrolled · warm · unconscious-seeking · distancing
flowclean-exit · extends-every-moment
deflectioninvisible · transparent-failing · none
sinceritydirect · warm-non-answer · rerouted-through-teasing · impossible
composureunbreakable · fragile
reads_targetaccurate · crashes
tells / speechauthored leaks · ref to voice subset
RESOLUTION (per turn)
  1. base               edge's authored default register (may be a HARD PIN)
  2. threshold selector  axis value → register variant  (e.g. trust gradient L1..L4)
  3. situational override event/context conditions       (romantic-interest → boundary_protection)
  4. emotional modulation current emotional state shifts the SURFACE, not the grammar
  5. mask + awareness    suppress specific content / gate whether she can name it

STORAGE   shared archetypes (one_way_mirror, romantic_deflection, ...) + card instantiation
          (binds archetype + character voice/tells). Bespoke card-local registers allowed.

NPC context assembly ADR 0007

The assembler is a compiler (structured data → folded prose blocks) and the isolation boundary. Compilation is LLM-driven; stable blocks are cached within a scene, volatile blocks (the snapshot) recompiled after deltas. Each NPC turn is two-stage: compile then act.

NPC_CALL for [character]:
  system:
    [IDENTITY]        card + knowledge_boundary (clamped to current chapter)
    [SELF]            internal state: mood, active emotions, motivation
    [SNAPSHOT]        edges → present chars, each axis as (value × awareness) language,
                      FOLDED (capped feelings never stated plainly), own-perspective only
    [MASKS]           topic_flags + global mask + active states
    [DIRECTIVES]      resolved register → concrete behavior rules
    [NUDGE]           directed-pressure nudge (ADR 0008), framed as the character's own impulse
    [SCENE RULES]     POV, tone, format
  user:
    [SCENE EXCERPT]   surface layer, POV-projected to this NPC (ADR 0009/0010): witnessed_by ∋ self
                      at fidelity (full / overheard / partial); perceived reads decoded via reads_target
    "How does [character] respond?"

Behavior translation (numbers → language), now 2-D ADR 0007

Extends the original 1-D table to (value × awareness). Major NPCs get the full card (Sonnet); minor NPCs a compressed card (Haiku).

affection +80..+100  "deeply fond, seeks closeness, visibly happy when near them"
affection +50..+79   "friendly, comfortable, generally cooperative"
affection +20..+49   "neutral to cautious, polite but guarded"

trust +25, low aware   "Something about [name] makes her hold back, though she couldn't say why."
trust +85, conscious   "She knows she doesn't fully trust [name]. She chooses her words carefully."
romantic +72, CAPPED   "A pull she has no name for — racing heart, words that won't form."
                       (never rendered as the plain feeling — the cap forbids it)

Psychological nudge — directed pressure ADR 0008

The nudge is the only channel from authorial / story intent into an NPC (everything else is self-simulation). It is a bias term gated by the register — it can justify a situational override or shift the surface, but is still gated by mask + awareness, so it never puppets. It is framed as the character's own impulse, never a stage direction.

ESCALATION LADDER (one beat, one character) — clocked by WORD BUDGET + goal-not-met
  L0 ambient → L1 preoccupation → L2 active intent → L3 urgent drive
  ── ceiling: never puppet from inside the character ──
  ① stall flag (out-of-context) → ② narrator environmental push → ③ player "Continue / Skip / Direct?"
  → ④ hard directive (break-glass; may override NPC; player-invoked; logged)

"Directed" = catchable, not scripted: the beat's goal is the anchor, the route may drift, and the chapter's word count is the outer hard flag. Authoring is dual — an omniscient beat intent (free text) is compiled into a knowledge-bounded nudge, or a nudge is hand-authored; both pass the leak-check at the assembler boundary. The nudge is the second leak guard (authorial omniscience).

POV projection + recorder ADR 0009/0010

POV is declared per scene (default from the chapter outline). The narrator writes in that contract, but each NPC's excerpt is re-projected to its own limited POV — the third leak guard (others' hidden truth + narrator omniscience). The recorder commits a two-layer record after each beat:

surface      observable behavior + dialogue + HEDGED perceived reads ("looks/seems X")  → crosses agents
true_state   per-character private feeling / intent  → NEVER cross-fed (own copy via SELF block)
witnessed_by { char: full | overheard | partial }     pov_anchor: <scene contract anchor>

Leak line: a perceived read ("Vixia looks sad") is fine; the truth behind it ("…because she's hiding the diagnosis", "he is lying") is not. Two per-edge, directional dials:

LEGIBILITY (how much shows)  baked into `surface` at the RECORDER
   = card base_opacity × axis intensity × awareness/mask × resolved register (composure+tells)   [target→observer edge]
DECODE (how well it's read)  applied per observer at PROJECTION
   = observer.reads_target   [observer→target edge]    accurate → faithful/sharpened · crashes → degraded

Poker-face = high card base_opacity (it seeds composure) — no new subsystem. Player delivery is sourced (prose → optional tone tag → narrator infer/ask), never decoded from text. Safety guard = the hedged-attribution rule (unhedged "is sad / is lying" rejected; hidden facts blocked by knowledge_boundary) + the shared review gate. Safety is structural (holds at any model tier); fidelity is best-effort + human-backstopped.

Three leak guards: own capped feelings (0007) · authorial omniscience (0008) · others' hidden truth + narrator omniscience (0009/0010). One review-gate surface now serves deltas (0003), nudge compile (0008), and beat records (0010).

NPC interaction queue core

After any speech act (player or NPC), each character present runs a priority check before anyone responds.

STEP 1 — Relevance check   directed at me? / touches my interests? / relationship urge? / motivation?
STEP 2 — Priority          RESPOND_NOW · RESPOND_WAIT · SILENT · INTERRUPT
STEP 3 — Interrupt valid    axis crosses threshold AND card supports behavior AND motivation strong
STEP 4 — Queue resolution   if no one responds → player inaction timer
PLAYER INACTION TIMER
  short  → other characters fill silence naturally
  medium → narrator describes atmosphere beat
  long   → system: "Continue? / Skip to next beat? / Direct a character?"

Context memory layers core

IMMEDIATE CONTEXT    raw exchanges, last ~2000 tokens
SCENE SUMMARY        compressed after each scene unit (also where drift + decay are applied)
CHAPTER LOG          key beat events for continuity
LOREBOOK             world facts, injected on keyword match (existing system)

Narrator resume anchor core

"You were narrating [scene type].
Last line before pause: '[exact last sentence]'
POV: [POV]. Tone: [tone].
Continue from here."
