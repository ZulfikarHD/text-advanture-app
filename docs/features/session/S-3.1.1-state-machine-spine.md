# S-3.1.1 — Session state machine spine

> **Status:** Built (skeleton subset) · **Domain:** session · depends-on [ADR 0016](../../adr/0016-narrator-agent-and-turn-loop.md) · preconditions S-2.1.1 (fork) + S-2.1.3 (loop state) · **Last Updated:** 2026-06-07

## Summary

The deterministic **spine** of the [session state machine](../../architecture/Diagrams/Engine/Session_State_Machine.md) — the single conductor that drives a save through `session_start → narrator_turn → { player_moment | beat_complete } → narrator_resumes`. It is the producer PH-37 reserved that moves a save off `session_start`. Implemented as `SessionStateMachine` ([`app/Services/SessionStateMachine.php`](../../../app/Services/SessionStateMachine.php)); S-3.1.2 ("the state machine is the only conductor") is satisfied structurally because one class owns the entire transition table.

## Goal & non-goals

- **Goal:** a deterministic, fail-closed transition table whose next node is decided **only** by the narrator turn's structured `Handoff`, so later sprints can plug their producers (prose call, player input, resume anchor) into a stable spine.
- **Non-goals:** generating prose / the handoff (S-4.2.1), committing player input (S-5.1.1), building the resume-anchor content (S-5.3.1), the Play advance UI (S-5.4.1), the `npc_moment` branch + recorder-first sequencing (Phase 2), and boundary subsystems (Phase 4).

## Transitions (each one guarded + persisted)

- `begin(PlaySession)` — `session_start → narrator_turn`. Loop entry.
- `applyHandoff(PlaySession, Handoff)` — `narrator_turn →` `player_moment` (`player_moment`) | `beat_complete` (`beat_complete`). `npc_moment` throws `IllegalLoopTransitionException::npcMomentNotReachable()` (Phase 2) and leaves the save unmoved.
- `resumeFromPlayerMoment(PlaySession)` — `player_moment → narrator_turn` on the **same** beat (`narrator_resumes` after the player acts).
- `completeBeat(PlaySession)` — `beat_complete →` reposition to the next beat in document order ([`BeatSequence`](../../../app/Services/BeatSequence.php)) `→ narrator_turn`. No next beat → holds on `beat_complete` (terminal, [PH-38](../../guides/PLACEHOLDER_TRACKING.md)).

Every transition fails closed with `IllegalLoopTransitionException` when called from the wrong node. The spine touches only `state_node` and the `current_*` position — no `events`, `resume_anchor`, or word/nudge clocks (those are S-5.2.1 / S-5.3.1 / Phase 4).

## Agent / isolation impact

Pure **Director/Engine** orchestration — no agent prompt is assembled or sent, no `true_state` or hidden fact is read. The spine is the conductor that later sequences recorder-first ordering (Phase 2) and boundary subsystems (Phase 4); it adds no new leak guard (ADR 0016 §5).

## Design notes

- **Injected handoff seam.** The handoff is an input to `applyHandoff()`, not produced here — so the spine is exercised by tests now and the prose call (S-4.2.1) wires its structured `handoff` field straight in without reshaping the machine.
- **Shared document order.** `BeatSequence` (`first(Story)` / `next(Beat)`, ordered `chapter.number → scene.number → beat.number`) is the single home for beat ordering; `SessionService::firstPlayableBeat()` was refactored to delegate to it so the fork and the spine never diverge.
- **No HTTP surface.** Backend-only this sprint; the advance/pause route arrives with the Play reader (S-5.4.1).
