# S-5.1.1 — Player moment input

> **Status:** Built · **Domain:** session · depends-on [ADR 0016](../../adr/0016-narrator-agent-and-turn-loop.md) · preconditions S-3.1.1 (spine) + S-4.2.1 (prose call) · **Last Updated:** 2026-06-08

## Summary

The **player half** of the narrator → me → narrator loop. When a narrator turn hands off with `player_moment`, the [Writing/Play page](../../architecture/Diagrams/Engine/Player_Moment_Flow.md) renders the composer; submitting commits the player's written contribution and continues the scene. The human supplies that character's behaviour — `is_player` is never simulated, so the engine does not generate the player's action.

Implemented as `SessionService::recordPlayerMoment()` ([`app/Services/SessionService.php`](../../../app/Services/SessionService.php)), called by `SessionController@input` ([`app/Http/Controllers/Stories/SessionController.php`](../../../app/Http/Controllers/Stories/SessionController.php)) and validated by `SubmitPlayerInputRequest`.

## Goal & non-goals

- **Goal:** at a player moment, the player writes prose, it enters the immediate context as the player's contribution, and the narrator resumes continuing from it — committed atomically so the loop never strands on a half-applied turn.
- **Non-goals:** generating the player's behaviour (`is_player` is human-driven), sourced delivery (prose → tone tag → infer/ask) and recording into the two-layer surface/`true_state` record (Phase 2, where an NPC witnesses the player's surface), the bounded immediate-context window + scene summary (S-5.2.1 remainder), the resume-anchor content (S-5.3.1).

## Behaviour

- **Atomic commit.** `recordPlayerMoment(save, content)` runs both writes inside one `DB::transaction`: it hands the turn back (`SessionStateMachine::resumeFromPlayerMoment`: `player_moment → narrator_turn`, **same beat**) and appends the input to the `events` scene log (`SceneLogService::recordPlayerInput`, anchored to the acted beat). A mid-turn failure rolls the whole moment back — the save stays on `player_moment` with nothing recorded (the same posture as `fork`/`reset`).
- **Off-turn fails closed.** The node guard runs first, so a `POST` when the save is not on `player_moment` throws `IllegalLoopTransitionException`; the controller surfaces an error toast and the save is untouched.
- **Validation.** `content` is required, `max:5000`; the composer mirrors the cap with a live character counter and disables Send past it.
- **Continue from it, don't restart.** The save keeps its beat — the next narrator turn (`narrate`) continues from the player's prose rather than restarting the beat.

## Agent / isolation impact

No agent prompt is assembled and no `true_state` is read — the input is recorded verbatim into the canonical prose history. No NPC consumes the player's surface yet (Phase 2), so there is no leak guard this phase (ADR 0016 §5).

## Design notes

- **Service over controller orchestration.** The two writes moved out of the controller into `SessionService::recordPlayerMoment()` so the transaction boundary lives with the lifecycle logic (matching `fork`/`reset`/`resume`), and the controller stays a thin gate-and-redirect.
- **Beat anchoring.** `current_beat_id` is captured **before** the spine advances, so the scene-log entry is anchored to the beat the player acted on, not whatever the spine moves to.
- **One turn control.** The Play page derives a `flow` prop from `state_node` so exactly one control is shown; the composer is autofocused on `awaitingPlayer` so writing back is immediate.
