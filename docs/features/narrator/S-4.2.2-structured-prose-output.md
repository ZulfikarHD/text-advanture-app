# S-4.2.1 / S-4.2.2 — Narrator structured prose call

> **Status:** Built (skeleton subset, backend + tests only) · **Domain:** narrator · **Owning ADR(s):** [ADR 0016](../../adr/0016-narrator-agent-and-turn-loop.md) (narrator turn / handoff), [ADR 0017](../../adr/0017-llm-orchestration-openrouter.md) (client/roles) · preconditions: [`NarratorPromptAssembler`](../../../app/Services/Narrator/NarratorPromptAssembler.php) (S-4.1.1), [`SessionStateMachine`](../../../app/Services/SessionStateMachine.php) (S-3.1.1), [`OpenRouterClient`](../../../app/Services/Llm/OpenRouterClient.php) (S-5.x), a stored provider key, seeded `prompt_blocks` + `model_profiles` · **Last Updated:** 2026-06-08

## Summary

The narrator turn — the **handoff producer** the state machine was built to consume (PH-37). [`NarratorTurnService`](../../../app/Services/Narrator/NarratorTurnService.php) assembles the registry-driven narrator prompt (S-4.1.1), resolves the `narrator_prose` model, and runs **one structured call** (via `LlmClient::completeStructured`) against [`NarratorProseSchema`](../../../app/Services/Narrator/NarratorProseSchema.php) that returns `prose · handoff · elapsed_bucket` together — so handoff detection is the prose call's own output, not a separate classifier pass. A validated result advances the loop spine by its `Handoff`; a malformed or failed call is retried to the bound, then surfaced as a failed turn that leaves the save unchanged (S-4.2.2). See the [Narrator turn diagram](../../architecture/Diagrams/Engine/Narrator_Turn_Prose_Call.md).

## Goal & non-goals

- **Goal (S-4.2.1):** run the full narrator prose call and route its structured `Handoff` into the spine — entering the loop on the opening turn, then advancing by the validated handoff.
- **Goal (S-4.2.2):** the loop never trusts an unparseable result. Malformed output — bad JSON, a missing field, a wrong type, **or an out-of-vocabulary enum value** — is retried within the transport bound, then recorded `Failed` and surfaced; the spine is never advanced on bad output.
- **Non-goals:** persisting the prose into the immediate-context `events` scene log (S-5.2.1, PH-40), the `resume_anchor` content (S-5.3.1), `elapsed_bucket` consumption by decay (Phase 5), the reachable advance control + prose reader (S-5.4.1, PH-41), the recorder sub-call + the `npc_moment` branch (Phase 2), and streaming/deferred UX (S-5.4.1).

## Behavior

`SessionController@narrate` (`POST stories.saves.narrate`, `update`-gated) delegates to `NarratorTurnService::run(PlaySession)`:

1. **Guard.** A narrator turn is valid only from `session_start` or `narrator_turn`; any other node throws `IllegalLoopTransitionException` **before** spending a call.
2. **Assemble + resolve.** Build the prompt messages (S-4.1.1) and resolve the `narrator_prose` `ModelProfile` (per-story override → global default) for the save's story.
3. **Call.** Run `completeStructured(request, NarratorProseSchema::definition(), NarratorProseSchema::NAME)`. The client retries 429/5xx + **malformed/non-conforming** output with backoff, logs the call, and throws `LlmStructuredOutputException` if it never conforms.
4. **Parse.** Map the validated payload into a readonly [`NarratorTurnResult`](../../../app/Services/Narrator/NarratorTurnResult.php) (`prose`, `Handoff`, `ElapsedBucket`).
5. **Advance (success only).** Because the call ran first, the spine is touched only now: `begin()` if the save was at `session_start`, then `applyHandoff(handoff)`.

On any failure the controller flashes an **error toast** and redirects to Play with the save **unchanged**; on success it flashes a **success toast** and redirects to Play at the advanced position.

## Data touched

Read-only for assembly/resolution (see S-4.1.1 + ADR 0017). Writes: `play_sessions.state_node` + `current_*` (via the spine, success only) and an append-only `llm_calls` row (Ok or Failed) by the client logger. **No** `events`/`resume_anchor`/clock writes this slice (deferred).

## Agent / isolation impact

Runs as the **Narrator** prose call (`narrator_prose` role), authenticated with the **owner's** key. The schema's `handoff` enum is deliberately narrowed to `player_moment | beat_complete` — `npc_moment` is a valid `Handoff` but its branch is not reachable until Phase 2, so the model can never route there. No `true_state` / hidden interiority is read (the prompt is the S-4.1.1 narrator assembly).

## Acceptance criteria

- [x] A validated payload advances the spine by its handoff (`player_moment` → `player_moment`, `beat_complete` → `beat_complete`); the opening turn enters the loop first.
- [x] Malformed output (incl. an out-of-vocabulary enum value) is retried to the bound, recorded as a `Failed` `llm_calls` row, and surfaced as an error toast — **state unchanged**.
- [x] The loop is **never advanced** on a failed/malformed call (the call runs before any transition).
- [x] Narrating off-turn is rejected with no call spent.
- [x] The endpoint is owner-scoped (foreign story → 404) and auth-gated (guest → login).
- [x] The validator enforces declared `enum` membership; schemas without an `enum` are unaffected (existing structured tests stay green).

## Open questions

- Should a surfaced narrator failure expose a one-tap **retry** affordance, or rely on the player re-triggering? (Decided with the Play reader UX, S-5.4.1.)
- Where does the prose/handoff/elapsed get **persisted** for scrollback + resume? (S-5.2.1 immediate-context `events`; this slice only returns the result.)
