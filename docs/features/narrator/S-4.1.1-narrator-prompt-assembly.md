# S-4.1.1 — Narrator prompt assembly

> **Status:** Built (skeleton subset) · **Domain:** narrator · **Owning ADR(s):** [ADR 0020](../../adr/0020-prompt-block-registry.md) (registry), [ADR 0016](../../adr/0016-narrator-agent-and-turn-loop.md) (context inventory), [ADR 0007](../../adr/0007-npc-context-assembly.md) (assembler shape) · preconditions: seeded `prompt_blocks` (Sprint 6), [`LorebookKeywordMatcher`](../../../app/Services/LorebookKeywordMatcher.php) (S-3.2.1), E1.2 structure, E3.1 spine · **Last Updated:** 2026-06-08

## Summary

The narrator half of the registry-driven prompt assembler. Given a save positioned at a narrator turn, [`NarratorPromptAssembler`](../../../app/Services/Narrator/NarratorPromptAssembler.php) reads the seeded `prompt_blocks` registry and folds each lit narrator block — `POV_CONTRACT`, `BEAT`, `LOREBOOK` (narrator), `SCENE_STATE`, `RESUME_ANCHOR` — into an ordered `AssembledPrompt`. Selection and order come entirely from the registry rows; a block whose producer is not built yet is absent with no filler. It produces chat messages only — the structured prose call (S-4.2.1) resolves the model and sends them.

## Goal & non-goals

- **Goal:** registry-driven assembly of exactly the narrator blocks lit this phase, ordered by `order_index` within `section`, each folded from its data producer — so the narrator has its registry-defined slots and nothing more.
- **Non-goals:** the LLM prose call + structured handoff (S-4.2.1), the `MESH_AWARENESS`/`DIRECTOR_STATE` producers (Phase 4), LLM-folding via `compile_instruction` (deferred — this phase folds deterministically, PH-25/PH-39), building the `resume_anchor` content (S-5.3.1), the immediate-context window + scene log (E5.2), and the NPC half of the assembler (Phase 2).

## Behavior

Runs inside the `narrator_turn` node of the [session state machine](../../architecture/Diagrams/Engine/Session_State_Machine.md) (invoked by the prose call, S-4.2.1):

1. **Build context** once from the save: current scene/beat/chapter, the story cast keyed by slug (current-chapter card eager-loaded for appearance), the lorebook with `minRevealChapter`, the latest scene summary, and `resume_anchor`. Cast + lorebook are read by `story_id` directly (neither is owner-scoped) so the turn assembles regardless of auth context.
2. **Select + order** the active registry rows for `agent IN (narrator, both)`, ordered by `section` then `order_index`.
3. **Fold** each row via the [`BlockProducer`](../../../app/Services/Narrator/Blocks/BlockProducer.php) registered for its key. No producer (MESH_AWARENESS, DIRECTOR_STATE) ⇒ skip; a producer that yields null/empty (RESUME_ANCHOR when not resuming, LOREBOOK with no match) ⇒ omit.
4. **Render** to messages: system blocks → one `system` message; user blocks → the `user` message, always closing with `Continue narrating.`

See the [Narrator prompt assembly diagram](../../architecture/Diagrams/Engine/Narrator_Prompt_Assembly.md).

## Data touched

Read-only (no migration). Producers source: `scenes` (`pov_mode`/`pov_anchor`/`tone`), `beats` (`goal`), `lorebook_entries` (`keywords`/`content`, reveal-gated by `chapters.number`), `characters` + `character_cards` (`name`/`appearance` via slug), `scene_summaries` (`summary`), `play_sessions` (`resume_anchor`, position FKs), and the global `prompt_blocks` registry. See [DATABASE.md §3.14](../../architecture/DATABASE.md) (`prompt_blocks`).

## Agent / isolation impact

Runs as the **Narrator** (omniscient, bound by the POV contract). The lit blocks carry leak rule `none` except `BEAT` = `omniscient_authoring` (author-side input, minimal goal-only this phase). The narrator `LOREBOOK` applies **no** `knowledge_boundary` clamp (omniscient), but still honours each entry's minimum-reveal-chapter gate via `LorebookKeywordMatcher::isWithheld()`. No `true_state` or hidden character interiority is read. `MESH_AWARENESS` (the `hedged_attribution` directive) arrives in Phase 4 with the relationship mesh.

## Acceptance criteria

- [x] The prompt carries only the registry blocks whose producers exist, ordered by `order_index` within `section`: `POV_CONTRACT`, `BEAT`, `LOREBOOK`, `SCENE_STATE`, (`RESUME_ANCHOR` when resuming).
- [x] Blocks with no producer yet (`MESH_AWARENESS`, `DIRECTOR_STATE`) are absent — no filler injected.
- [x] Block selection and order come from `order_index`/`section`/`is_active` rows, not code constants (reordering or deactivating a row changes the output).
- [x] `RESUME_ANCHOR` is injected only when the session is resuming (`resume_anchor` set).

## Open questions

- Does the assembler eventually LLM-fold rich blocks via `compile_instruction` (the `compiler` role), or keep deterministic template-fold for cheap blocks? (ADR 0020 open question; this phase template-folds all — PH-39.)
- What is the canonical lorebook sample text once committed prose history exists (E5.2)? This phase samples the authored scene surface (setting, tone, anchor, goal, present cast, summary).
